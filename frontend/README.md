# AI Skin Intelligence - Frontend

The frontend for **AI Skin Intelligence**, an AI-powered skincare analysis and recommendation platform.

It provides the user interface for authentication, skin image analysis, personalized recommendations, analysis history, analytics, weekly skincare planning, and the AI skincare assistant.

The frontend is built with **Next.js, React, TypeScript, and Tailwind CSS** and communicates with the FastAPI backend through REST APIs.

## Features

### Core Features

* **Authentication**: User registration and login with JWT-based authentication
* **Skin Image Analysis**: Upload skin images for backend-based analysis
* **Skin Prediction**: Display skin-related predictions returned by the backend
* **Personalized Recommendations**: Display skincare recommendations generated by the recommendation pipeline
* **Weekly Skincare Plan**: Display a structured skincare routine
* **Analysis History**: View previous skin analyses
* **Analytics Dashboard**: Visualize available skin analysis data and trends
* **AI Assistant**: Chat with the skincare assistant
* **User Settings**: Manage available user preferences and account settings

### Technical Highlights

* Responsive UI built with Tailwind CSS
* Client-side API communication using Axios
* Data fetching and caching using SWR
* Global authentication state using Zustand
* Smooth UI animations using Framer Motion
* Data visualization using Recharts
* Type-safe frontend development with TypeScript and Zod

## Getting Started

### Prerequisites

* Node.js 18+
* pnpm
* FastAPI backend running at `http://127.0.0.1:8000`

### Installation

1. Clone the repository:

```bash
git clone <repository-url>
```

2. Navigate to the frontend directory:

```bash
cd frontend
```

3. Install dependencies:

```bash
pnpm install
```

4. Create a `.env.local` file in the frontend directory:

```env
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

5. Start the development server:

```bash
pnpm dev
```

6. Open:

```text
http://localhost:3000
```

The `NEXT_PUBLIC_API_URL` variable specifies the FastAPI backend URL used by the frontend.

## API Integration

Frontend API requests are centralized through `lib/api.ts`.

The API client is responsible for:

* Backend base URL configuration
* JWT token attachment
* Authentication-related request handling
* HTTP error handling
* Communication with the FastAPI backend

### Backend Endpoints

The frontend communicates with the FastAPI backend through the following endpoints:

```text
GET    /
GET    /health

POST   /predict
POST   /compare

POST   /register
POST   /login
GET    /history

GET    /test-groq
POST   /assistant
```

These endpoints are defined by the backend FastAPI application. The `/assistant` route is also exposed through the backend assistant routing module.

## Authentication Flow

1. User opens the application.
2. Unauthenticated users are directed to the login page.
3. User registers or logs in through the authentication API.
4. The JWT token is stored by the frontend authentication state.
5. Authenticated API requests include the token.
6. The user completes onboarding when required.
7. Protected pages become available.

Protected application areas include:

* Dashboard
* Upload / Analysis
* History
* Analytics
* Assistant
* Settings

## Development Guidelines

### Adding Pages

Create a new route inside the `app/` directory:

```text
app/[section]/page.tsx
```

Use the existing protected layout for pages that require authentication.

### Data Fetching

Use SWR where appropriate for:

* Client-side API data fetching
* Caching
* Revalidation

After data-changing operations, use SWR's `mutate()` functionality when the affected data needs to be refreshed.

### Styling

* Use Tailwind CSS utility classes.
* Follow the existing application's creamy skincare-oriented visual design.
* Prefer reusable components over duplicated UI code.
* Maintain responsive behavior across screen sizes.
* Keep the existing design language consistent when adding new pages.

### TypeScript

Use the existing TypeScript types in `lib/types.ts` and maintain type-safe API interactions.

## Environment Variables

For local development, create:

```text
frontend/.env.local
```

with:

```env
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

Do **not** commit `.env.local` or any file containing private credentials.

The repository includes `.env.example` as a template for the required frontend environment configuration.

## Build

To create a production build:

```bash
pnpm build
```

To run the production build locally:

```bash
pnpm start
```

## Deployment

The frontend can be deployed to a Next.js-compatible hosting platform such as Vercel.

Before deployment:

1. Configure the production `NEXT_PUBLIC_API_URL`.
2. Ensure the FastAPI backend is accessible from the deployed frontend.
3. Verify authentication and API communication.
4. Run the production build locally.
